# HL open-launch / uncapped inventory (draft)

Read-only inventory, worktree `dv-hl-open` at `726378d`. Lists every past Hyperliquid review item (finding, verdict,
accepted risk, mitigation, GO / readiness / deploy condition, design risk, executor item) whose argument relied on
(a) restricted launch (`openLaunch = false`, launcher allowlist, vetted / trusted / few managers, "platform-run"),
or (b) a bounded size (`maxDepositCap` <= 50,000 USDC, bounded NAV / position / bridge amounts, HyperCore limits,
small-scale rounding, USDC loss bounds that scale with the cap). Gains reviews ignored except `gov/HL-RETEST.md`.

The change under review: commits `0b6a0c0` / `6dfb9ae` (2026-10-13). `Deploy.s.sol:169` now defaults
`MAX_DEPOSIT_CAP` to `type(uint256).max` (0 refused); the factory constructor still defaults `maxDepositCap = 50_000e6`
(`HyperVaultFactory.sol:60`), so "uncapped" is a factory-owner `setMaxDepositCap(max)` per factory plus per-vault
`depositCap = max`. `openLaunch` is a factory-owner setting (`HyperVaultFactory.sol:206-207, 369`); the deploy script
never sets it, the webapp `/launch` was opened for everyone in `6dfb9ae`. Whether `openLaunch` is true on chain is not
checked here.

Legend: "Breaks" = open launch (OL), cap (CAP), both. "Guess" is the drafter's initial guess only, not a verdict.
